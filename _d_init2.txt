   1| """
   2| solver_sardine
   3| ==============
   4| Python-native re-implementation of the SardineCan *Extreme Point Insertion*
   5| heuristic (see ``sardine-can/SC.Core/Heuristics/PrimalHeuristic/
   6| ExtremePointInsertion.cs``), adapted so it consumes the **same Excel /
   7| sidebar manifest** and produces the **same output shape** as the classic
   8| py3dbp engine in ``app.py``.
   9| 
  10| Key behaviours ported from the C# engine:
  11| 
  12| * **Extreme Points** — the container maintains a set of empty-space
  13|   *extreme points* (corner vertices of already-placed items + container
  14|   walls).  Every feasible item is tried at each extreme point instead of
  15|   the py3dbp brute-force pivot sweep.
  16| * **Best-fit merit** — for each (item, EP, rotation) the candidate whose
  17|   *minimum residual slack* across all three axes is largest is chosen
  18|   (the "best-fit" / MEDXYZ spirit).
  19| * **Support / stability** — identical 0.75 surface-ratio rule used
  20|   elsewhere in the codebase; the item's bottom footprint must be ≥ 75 %
  21|   supported (or on the floor with no floating).
  22| * **Orientation policy** — honours the *already-chosen* pose from
  23|   ``orientation_editor`` (stored as ``w/h/d`` in meters).  ``updown``
  24|   semantics map to rotation-type filtering: a non-tip-able item may only
  25|   spin on the floor (``RT_WHD`` / ``RT_DHW``), never tip onto another
  26|   face — exactly like ``RotationType.Notupdown`` in the classic engine.
  27| * **Sequence / LIFO** — when ``prioritize_sequence`` is on, items are
  28|   sorted highest-sequence-first (deepest first) and the same
  29|   soft-LIFO accessibility guard used by ``pack_soft_lifo`` in
  30|   ``app.py`` is enforced at placement.
  31| 
  32| The solver is structured so the **baseline** (``solver_sardine.baseline``
  33| ``solve_sardine``) always produces a valid layout equivalent to the
  34| classic engine's, while the optional **improver**
  35| (``solver_sardine.improver``) is free to try alternative strategies and
  36| only replaces the baseline result when it is *strictly better* on the
  37| same composite score.
  38| """
